   362→OWNER, GROUP, AND OTHER PERMISSIONS
   363→Every file and directory has three types of access:
   364→Owner (user), Group, and Other (everyone else).
   365→Permissions control what each can do.
   366→
   367→READ, WRITE, AND EXECUTE
   368→
   369→R (read): View file contents or list directory.
   370→
   371→W (write): Modify file or create/delete in directory.
   372→X (execute): Run file or access directory.
   373→
   374→NUMERIC AND SYMBOLIC PERMISSIONS
   375→Numeric: Use numbers (0-7) to represent permissions.
   376→Symbolic: Use letters (r, w, x) to set permissions.
   377→Example: 755 = rwxr-xr-x
   378→
   379→CHMOD, CHOWN, CHGRP
   380→
   381→chmod _: Change file or directory permissions
   382→chown _: Change file or directory owner
   383→chgrp_: Change file or directory group
   384→
   385→DIRECTORY PERMISSION BEHAVIOR
   386→Read (r): List files in the directory
   387→
   388→Write (w): Create, delete, or rename files
   389→Execute (x): Enter and access the directory
   390→Without x, you cannot access files inside.
   391→
   392→UMASK
   393→
   394→The umask sets default permissions for new files
   395→and directories.
   396→
   397→It determines what permissions are removed by
   398→default.
   399→
   400→Check with: umask
   401→
   402→FINDING DANGEROUS PERMISSIONS
   403→Look for world-writable files and directories.
   404→Use tools to find risky permissions.
   405→
   406→Example: chmod 777 or writable system files.
   407→Command: find / -type f -perm -002 -Is
   408→
   409→PRODUCTION PERMISSION MISTAKES
   410→
   411→¢ Using 777 permissions
   412→
   413→* Making sensitive files world-readable
   414→
   415→* Incorrect ownership of application files
   416→
   417→* Writable permissions on critical system directories
   418→* Ignoring umask settings

   498→SGID on files: Runs with the group owner's privileges.
   499→SGID on directories: New files inherit the directory’s
   500→
   501→SGID group ownership.
   502→Helps in controlled group collaboration.
   503→STICKY BIT
   504→On directories, only the file owner, directory owner,
   505→or root can delete or rename files.

   507→
   508→each other's files.

  1180→A host-based firewall controls network traffic to and from

  1184→at the host level.

  1187→
  1188→nftables is the modern Linux packet filtering framework.
  1189→It is powerful, fast, and replaces legacy iptables.
  1190→
  1191→It supports complex rules, sets, maps, and stateful filtering.
  1192→
  1193→IPTABLES CONCEPTS
  1194→
  1195→iptables is the legacy firewall tool based on tables, chains,
  1196→and rules. Key tables: filter, nat, mangle, raw.
  1197→
  1198→Key chains: INPUT, OUTPUT, FORWARD.
  1199→

  1201→

  1203→firewalld provides a dynamic firewall with zones,
  1204→services, and runtime management.
  1205→
  1206→DEFAULT-DENY STRATEGY
  1207→
  1208→Start with default deny for incoming connections.
  1209→Allow only what is required. This minimizes risk by
  1210→blocking everything except explicitly allowed traffic.
  1211→
  1212→INBOUND VERSUS OUTBOUND RULES
  1213→Inbound rules control traffic coming into the system.
  1214→Outbound rules control traffic leaving the system.
  1215→Both should be defined intentionally.
  1216→
  1217→RESTRICTING ADMINISTRATIVE PORTS
  1218→Limit access to administrative ports (SSH, RDP, etc.)
  1219→to trusted IPs or networks only.
  1220→
  1221→Never expose admin ports to the public internet.
  1222→
  1223→RULE ORDERING
  1224→
  1225→Firewall rules are processed in order from top to bottom.
  1226→Place specific allow rules before general deny rules.
  1227→Incorrect ordering can create security gaps.
  1228→
  1229→PERSISTENT FIREWALL CONFIGURATION
  1230→
  1231→Firewall rules must survive reboots.
  1232→Use appropriate tools to save rules:
  1233→
  1234→nft list ruleset > file, iptables-save, ufw enable, firewalld --permanent.

  1236→TESTING RULES WITHOUT LOCKING YOURSELF OUT
