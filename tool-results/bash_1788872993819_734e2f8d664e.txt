OWNER, GROUP, AND OTHER PERMISSIONS
Every file and directory has three types of access:
Owner (user), Group, and Other (everyone else).
Permissions control what each can do.

READ, WRITE, AND EXECUTE

R (read): View file contents or list directory.

W (write): Modify file or create/delete in directory.
X (execute): Run file or access directory.

NUMERIC AND SYMBOLIC PERMISSIONS
Numeric: Use numbers (0-7) to represent permissions.
Symbolic: Use letters (r, w, x) to set permissions.
Example: 755 = rwxr-xr-x

CHMOD, CHOWN, CHGRP

chmod _: Change file or directory permissions
chown _: Change file or directory owner
chgrp_: Change file or directory group

DIRECTORY PERMISSION BEHAVIOR
Read (r): List files in the directory

Write (w): Create, delete, or rename files
Execute (x): Enter and access the directory
Without x, you cannot access files inside.

UMASK

The umask sets default permissions for new files
and directories.

It determines what permissions are removed by
default.

Check with: umask

FINDING DANGEROUS PERMISSIONS
Look for world-writable files and directories.
Use tools to find risky permissions.

Example: chmod 777 or writable system files.
Command: find / -type f -perm -002 -Is

PRODUCTION PERMISSION MISTAKES

¢ Using 777 permissions

* Making sensitive files world-readable

* Incorrect ownership of application files

* Writable permissions on critical system directories
* Ignoring umask settings

10. LINUX FIREWALL SECURITY

Fie

HOST-BASED FIREWALL PURPOSE

A host-based firewall controls network traffic to and from
your Linux system. It blocks unauthorized access,
reduces attack surface, and enforces security policies

at the host level.

NFTABLES

nftables is the modern Linux packet filtering framework.
It is powerful, fast, and replaces legacy iptables.

It supports complex rules, sets, maps, and stateful filtering.

IPTABLES CONCEPTS

iptables is the legacy firewall tool based on tables, chains,
and rules. Key tables: filter, nat, mangle, raw.

Key chains: INPUT, OUTPUT, FORWARD.

UFW AND FIREWALLD

UFW is a simple frontend for iptables/nftables.
firewalld provides a dynamic firewall with zones,
services, and runtime management.

DEFAULT-DENY STRATEGY

Start with default deny for incoming connections.
Allow only what is required. This minimizes risk by
blocking everything except explicitly allowed traffic.

INBOUND VERSUS OUTBOUND RULES
Inbound rules control traffic coming into the system.
Outbound rules control traffic leaving the system.
Both should be defined intentionally.

RESTRICTING ADMINISTRATIVE PORTS
Limit access to administrative ports (SSH, RDP, etc.)
to trusted IPs or networks only.

Never expose admin ports to the public internet.

RULE ORDERING

Firewall rules are processed in order from top to bottom.
Place specific allow rules before general deny rules.
Incorrect ordering can create security gaps.

PERSISTENT FIREWALL CONFIGURATION

Firewall rules must survive reboots.
Use appropriate tools to save rules:

nft list ruleset > file, iptables-save, ufw enable, firewalld --permanent.

TESTING RULES WITHOUT LOCKING YOURSELF OUT

Always test firewall changes carefully.
Use a second SSH session or console access.
Apply changes gradually and verify before closing your session.

FAILED AUTHENTICATION

SERVICE FAILURES

Helps detect misconfigurations and potential attacks.

KERNEL MESSAGES

Kernel logs report hardware, driver, and system events.
Important for detecting panics, OOM kills, and security issues.

MANDATORY ACCESS CONTROL

SELinux and AppArmor are Mandatory Access Control (MAC)
systems that restrict what processes can do,

SELinux even if they are compromised or running as root.

SELINUX MODES
SELinux operates in three main modes
that determine how policies are enforced.

ENFORCING, PERMISSIVE, AND DISABLED
DISABLED + Enforcing: Policies are active and violations are blocked.
+ Permissive: Policies are active but violations are only logged.

* Disabled: SELinux is turned off (not recommended).

SELINUX CONTEXTS

SELinux uses security contexts (labels) to define

what users, roles, types, and levels a process or file has.
Contexts control access decisions.

POLICY VIOLATIONS

When a process is blocked by SELinux,

an AVC (Access Vector Cache) denial is logged.
These logs show what was blocked and why.

GETENFORCE

getenforce shows the current SELinux mode.
Command: getenforce

Example output: Enforcing | Permissive | Disabled

SESTATUS

sestatus displays SELinux status, mode,
policy type, and other important details.
Command: sestatus

APPARMOR PROFILES

AppArmor uses profiles to restrict programs.

Each profile defines what the program can access.
AppArmor Profiles are stored in /etc/apparmor.d/

ENFORCE VERSUS COMPLAIN MODE
ei vs GY + Enforce: Violations are blocked.
+ Complain: Violations are logged but not blocked.

Use complain mode to test profiles before enforcing.

TROUBLESHOOTING BLOCKED APPLICATIONS SAFELY
+ Review AVC logs: ausearch -m ave -ts recent

+ Identify the blocked action and target.

+ Adjust the policy or profile.

+ Use permissive or complain mode during troubleshooting.

+ Return to Enforcing/Enforce mode after validation.
