   363→   363→OWNER, GROUP, AND OTHER PERMISSIONS

   369→   369→
   370→   370→R (read): View file contents or list directory.
   371→   371→
   372→   372→W (write): Modify file or create/delete in directory.
   373→   373→X (execute): Run file or access directory.
   374→   374→
   375→   375→NUMERIC AND SYMBOLIC PERMISSIONS
   376→   376→Numeric: Use numbers (0-7) to represent permissions.
   377→   377→Symbolic: Use letters (r, w, x) to set permissions.
   378→   378→Example: 755 = rwxr-xr-x

   380→   380→CHMOD, CHOWN, CHGRP
   381→   381→
   382→   382→chmod _: Change file or directory permissions
   383→   383→chown _: Change file or directory owner
   384→   384→chgrp_: Change file or directory group

   386→   386→DIRECTORY PERMISSION BEHAVIOR
   387→   387→Read (r): List files in the directory
   388→   388→
   389→   389→Write (w): Create, delete, or rename files
   390→   390→Execute (x): Enter and access the directory
   391→   391→Without x, you cannot access files inside.

  1179→  1179→HOST-BASED FIREWALL PURPOSE
  1180→  1180→
  1181→  1181→A host-based firewall controls network traffic to and from
  1182→  1182→your Linux system. It blocks unauthorized access,
  1183→  1183→reduces attack surface, and enforces security policies
  1184→  1184→
  1185→  1185→at the host level.
  1186→  1186→
  1187→  1187→NFTABLES
  1188→  1188→
  1189→  1189→nftables is the modern Linux packet filtering framework.
  1190→  1190→It is powerful, fast, and replaces legacy iptables.
  1191→  1191→
  1192→  1192→It supports complex rules, sets, maps, and stateful filtering.
  1193→  1193→
  1194→  1194→IPTABLES CONCEPTS
  1195→  1195→
  1196→  1196→iptables is the legacy firewall tool based on tables, chains,
  1197→  1197→and rules. Key tables: filter, nat, mangle, raw.
  1198→  1198→
  1199→  1199→Key chains: INPUT, OUTPUT, FORWARD.
  1200→  1200→
  1201→  1201→UFW AND FIREWALLD
  1202→  1202→
  1203→  1203→UFW is a simple frontend for iptables/nftables.
  1204→  1204→firewalld provides a dynamic firewall with zones,
  1205→  1205→services, and runtime management.
  1206→  1206→
  1207→  1207→DEFAULT-DENY STRATEGY
  1208→  1208→
  1209→  1209→Start with default deny for incoming connections.
  1210→  1210→Allow only what is required. This minimizes risk by
  1211→  1211→blocking everything except explicitly allowed traffic.
  1212→  1212→
  1213→  1213→INBOUND VERSUS OUTBOUND RULES
  1214→  1214→Inbound rules control traffic coming into the system.
  1215→  1215→Outbound rules control traffic leaving the system.
  1216→  1216→Both should be defined intentionally.
  1217→  1217→
  1218→  1218→RESTRICTING ADMINISTRATIVE PORTS
  1219→  1219→Limit access to administrative ports (SSH, RDP, etc.)
  1220→  1220→to trusted IPs or networks only.
  1221→  1221→
  1222→  1222→Never expose admin ports to the public internet.
  1223→  1223→
  1224→  1224→RULE ORDERING
  1225→  1225→
  1226→  1226→Firewall rules are processed in order from top to bottom.
  1227→  1227→Place specific allow rules before general deny rules.
  1228→  1228→Incorrect ordering can create security gaps.
  1229→  1229→
  1230→  1230→PERSISTENT FIREWALL CONFIGURATION
  1231→  1231→
  1232→  1232→Firewall rules must survive reboots.
  1233→  1233→Use appropriate tools to save rules:
  1234→  1234→
  1235→  1235→nft list ruleset > file, iptables-save, ufw enable, firewalld --permanent.
  1236→  1236→
  1237→  1237→TESTING RULES WITHOUT LOCKING YOURSELF OUT
  1238→  1238→
  1239→  1239→Always test firewall changes carefully.
  1240→  1240→Use a second SSH session or console access.
  1241→  1241→Apply changes gradually and verify before closing your session.
