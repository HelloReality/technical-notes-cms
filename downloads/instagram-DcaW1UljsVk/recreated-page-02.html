1. What Is Shell Scripting?
Shell · Terminal · Bash · And Why DevOps Engineers Script
Shell vs Terminal vs Bash
TERMINAL — The application you open. A text interface to interact with the computer.
SHELL — The program that interprets your commands and talks to the OS.
BASH — The most common shell on Linux. "Bourne Again SHell". Command language + scripting interpreter.
What a Shell Actually Does
1Reads your command.
2Parses (understands) the command.
3Expands variables, wildcards, and paths.
4Executes the command or program.
5Returns the output and exit status.
6Waits for the next command.
User → Shell → Kernel → Output
Why DevOps Engineers Automate with Scripts
  • Save time and reduce manual work.
  • Eliminate human errors.
  • Ensure repeatability and consistency.
  • Scale operations easily.
  • Automate deployments, monitoring, backups.
  • Integrate with CI/CD pipelines.
  • Improve reliability and speed.
Interactive Commands vs Scripts
Interactive CommandsScripts
You type and run one command at a time.You write commands in a file and run them.
Used for ad-hoc tasks.Used for automation.
Hard to repeat.Repeatable and consistent.
Not version controlled.Version controlled (Git).
Easy to forget commands.Easy to share and reuse.
Your First Bash Script
hello.sh
#!/bin/bash
# This is my first script
echo "Hello, DevOps Engineer!"
DATE=$(date)
echo "Today is: $DATE"
Shebang tells the system to use Bash · Comment is ignored · echo prints to screen · $(date) stores current date in a variable.
Running a Script Safely
1Create the file
nano myscript.sh
2Save and exit
CTRL + O, ENTER, CTRL + X
3Make it executable
chmod +x myscript.sh
4Run the script
./myscript.sh
Best Practices
  • Review your script before running.
  • Use full paths for important commands.
  • Test in a safe environment first.
Important Note A script has the same power as the user who runs it. Always review scripts before executing — especially scripts downloaded from the internet.
