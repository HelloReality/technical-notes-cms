13. REDIRECTION, PIPES, AND LOGS

— CONTROL OUTPUT. CAPTURE LOGS. DEBUG SMARTER. —
1 STANDARD INPUT (STDIN)

Input from keyboard or file.

bash
command < file.txt
sort < names.txt
2 STANDARD OUTPUT (STDOUT)

Normal command output.

bash
ls -l
echo "Hello"
3 STANDARD ERROR (STDERR)

Error messages and warnings.

bash
ls no_file
cat no_file.txt
4 OUTPUT REDIRECTION

Overwrite output to a file.

bash
command > file.log
OVERWRITE FILE
5 APPEND REDIRECTION

Append output to a file.

bash
command >> file.log
APPEND TO FILE
6 ERROR REDIRECTION

Redirect errors to a file.

bash
command 2> error.log
ERRORS ONLY
7 COMBINE STDOUT AND STDERR

Send both output and errors to same file.

bash
command > output.log 2>&1
OUTPUT + ERRORS TOGETHER
8 PIPES (|)

Send output of one command as input to another.

bash
ps aux | grep nginx | wc -l
FILTER AND PROCESS DATA
9 SEND SCRIPT OUTPUT TO LOG FILES

Log everything for monitoring and audits.

bash
#!/bin/bash
echo "Starting script..." > script.log
ls -l /var/log >> script.log
df -h >> script.log
echo "Script completed." >> script.log
10 CAPTURING ERRORS SEPARATELY

Keep success and errors in different files.

bash
#!/bin/bash
command > success.log 2> error.log
echo "Done" >> success.log
SUCCESS .LOGERROR .LOG
11. Common Examples
CommandDescription
ls -l > files.txt→ Save output to file (overwrite)
ls -l >> files.txt→ Append output to file
command 2> error.log→ Save errors to error.log
command > all.log 2>&1→ Save output and errors to all.log
command | grep "pattern"→ Filter output using grep
cat access.log | grep 404 | wc -l→ Count 404 errors in logs
BEST PRACTICES
  • Log important outputs.
  • Separate errors from normal output.
  • Use append (>>) for long-running logs.
  • Use pipes to analyze data.
  • Always check your logs.
  • Keep logs organized and rotate them.
