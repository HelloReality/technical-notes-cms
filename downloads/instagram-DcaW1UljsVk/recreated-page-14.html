13. REDIRECTION, PIPES, AND LOGS

CONTROL OUTPUT. CAPTURE LOGS. DEBUG SMARTER.
1 STANDARD INPUT (STDIN)

Read input from keyboard or another command.

KEYCMD
2 STANDARD OUTPUT (STDOUT)

Default output goes to the screen.

CMDSCREEN
3 STANDARD ERROR (STDERR)

Error messages go to a separate stream.

CMDERROR
4 OUTPUT REDIRECTION (>)

Overwrite a file with command output.

redir.sh
echo "Hello" > file.txt
ls > listing.txt

Creates or overwrites the file.

5 APPEND REDIRECTION (>>)

Append output to an existing file.

append.sh
echo "Line 2" >> file.txt
date >> log.txt

Adds without overwriting.

6 ERROR REDIRECTION (2>)

Send errors to a separate file.

err-redir.sh
ls /missing 2> errors.log
7 COMBINE STDOUT & STDERR (2>&1)

Send both output and errors to one file.

combine.sh
cmd > all.log 2>&1
8 PIPES (|)

Send one command's output to another.

pipe.sh
cat log | grep ERR | wc -l
9 SEND SCRIPT OUTPUT TO LOG FILES

Inside a script, redirect everything.

script-log.sh
#!/bin/bash
LOG="/var/log/myscript.log"
echo "Starting..." > "$LOG"
apt update >> "$LOG" 2>&1
echo "Done." >> "$LOG"
10 CAPTURING ERRORS SEPARATELY

Split success and error streams.

split-log.sh
cmd > success.log 2> error.log
success.log
STDOUT only
error.log
STDERR only
11COMMON EXAMPLES
cmd > fileOverwrite file
cmd >> fileAppend to file
cmd 2> fileErrors to file
cmd > file 2>&1Both to file
cmd | lessPage output
cmd | tee fileShow & save
cmd < fileRead from file
cmd1 | cmd2Pipe output
BEST PRACTICES
Always log script output to a file.
Separate STDOUT and STDERR when debugging.
Use >> to append, not overwrite.
Use tee to see and save output.
Rotate logs to avoid disk bloat.
Validate exit codes with $?.
