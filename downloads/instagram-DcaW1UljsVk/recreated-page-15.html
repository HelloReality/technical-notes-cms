14.PROCESSES AND SERVICES

Monitor. Control. Keep everything running.
1PS – VIEW PROCESSES

Show running processes.

ps.sh
ps aux ps -ef

Useful columns:

  • PID – Process ID
  • USER – Owner
  • %CPU, %MEM – Usage
  • COMMAND – Process name
2PGREP – FIND PROCESSES

Find process IDs by name.

pgrep.sh
pgrep nginx pgrep -f myapp

Used for scripting and automation.

3KILL – STOP PROCESSES

Stop processes using PID.

kill.sh
kill 1234 kill -9 1234
  • kill – graceful (SIGTERM)
  • kill -9 – force (SIGKILL)
Use kill -9 only when needed.
4SYSTEMCTL – MANAGE SERVICES

Control system services (Linux).

systemctl.sh
systemctl start nginx systemctl stop nginx systemctl restart nginx systemctl enable nginx

Works with systemd services.

5CHECK IF PROCESS RUNNING

Check if a process is running.

check-proc.sh
pgrep nginx >/dev/null if [ $? -eq 0 ]; then echo "Running" else echo "Not running" fi

Exit code 0 = running

6CHECK SERVICE STATUS

Check status of a service.

status.sh
systemctl status nginx

Common states:

  • ● active (running)
  • ● inactive (dead)
  • ! failed
7RESTART FAILED SERVICES

Restart a service.

restart.sh
systemctl restart nginx systemctl enable nginx systemctl status nginx

Auto-restart on boot + check again.

8PROCESS INFORMATION

Get more details about a process.

ps-info.sh
ps -p 1234 -o pid,user,cmd,%mem,%cpu ps -o pid,ppid,cmd -p 1234

Show parent process with ppid.

9BASIC SERVICE HEALTH CHECK

Example: Check and restart service.

health.sh
#!/bin/bash SERVICE=nginx pgrep $SERVICE >/dev/null if [ $? -eq 0 ]; then echo "$SERVICE is running" else echo "$SERVICE is down. Restarting..." systemctl restart $SERVICE fi
10QUICK REFERENCE
1ps aux
2pgrep <name>
3kill <PID>
4kill -9 <PID>
5systemctl status <svc>
6systemctl restart <svc>
7systemctl enable <svc>
8journalctl -u <svc>
  • List, find, stop, manage, and view logs
BPBEST PRACTICES
  • Always check before you kill.
  • Use meaningful process names.
  • Monitor important services.
  • Automate health checks.
  • Log issues for faster troubleshooting.
  • Restart only when necessary.
  • Keep scripts simple and readable.
Key Takeaway
Know your processes. Control your services. Keep your systems reliable.
