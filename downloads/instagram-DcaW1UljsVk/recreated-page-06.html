4. VARIABLES AND ENVIRONMENT VARIABLES

STORE DATA. REUSE. AUTOMATE.

1. Creating Variables

No spaces around = sign.

variables.sh
NAME=DevOps
COUNT=5

2. Reading Variables

Use $ to read a variable.

read.sh
$ echo $NAME
DevOps

3. Quoting Variables

  • •Use quotes to handle spaces.
  • •Prevents word splitting.
  • •Prevents filename expansion.
quote.sh
$ echo "$NAME"
$ echo '$NAME'

4. Command Substitution

Store the output of a command.

substitution.sh
$ DATE=$(date +%Y-%m-%d)
$ echo $DATE
2025-05-18

5. Export Variables

  • •Makes a variable available to child processes.
  • •Use export.
export.sh
$ export PROJECT=MyApp
$ echo $PROJECT
MyApp

6. Environment Variables

Set by the system. Available in every shell.

env.sh
$ echo $HOME
$ echo $USER
$ echo $SHELL
$ echo $LANG
Common Env Variables
VarMeaningExample
$HOMEYour home directory/home/user
$USERCurrent logged-in useruser
$PATHCommand search dirs/usr/bin:/bin:/usr/local/bin
8. Using Variables in Scripts
app.sh
#!/bin/bash
APP_NAME="MyApp"
LOG_DIR="$HOME/logs"
mkdir -p "$LOG_DIR"
echo "Starting $APP_NAME...."
echo "Logs will be saved in $LOG_DIR"
9. Best Practices
  • ✓Always use quotes when in doubt.
  • ✓Use meaningful variable names.
  • ✓Export only what you need.
  • ✓Keep variables uppercase for constants.
  • ✓Use command substitution $( ) often.
  • ✓Test your scripts with different values.
