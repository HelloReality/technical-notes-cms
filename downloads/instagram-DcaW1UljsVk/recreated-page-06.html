4. Variables and Environment Variables

Store data. Reuse. Automate.
1. Creating Variables
  • No spaces around = sign.
NAME=DevOps COUNT=5
2. Reading Variables
  • Use $ to read a variable.
echo $NAME
Output: DevOps
3. Quoting Variables
  • Use quotes to handle spaces.
  • Prevents word splitting.
  • Prevents filename expansion.
echo "$NAME" echo '$NAME'
4. Command Substitution
  • Store the output of a command.
DATE=$(date +%Y-%m-%d) echo $DATE
Output: 2025-05-18
5. Export Variables
  • Makes a variable available to child processes.
  • Use export.
export PROJECT=MyApp echo $PROJECT
Output: MyApp
6. Environment Variables
  • Set by the system.
  • Available in every shell.
bash
echo $HOME echo $USER echo $SHELL echo $LANG
HOME
Your home directory.
echo $HOME
Output: /home/user
USER
Current logged-in user.
echo $USER
Output: user
PATH
Directories where commands are searched.
echo $PATH
Output: /usr/bin:/bin:/usr/local/bin
8. Using Variables in Scripts
  • Make your scripts flexible and powerful.
bash
#!/bin/bash APP_NAME="MyApp" LOG_DIR="$HOME/logs" mkdir -p "$LOG_DIR" echo "Starting $APP_NAME...." echo "Logs will be saved in $LOG_DIR"
9. Best Practices
  • Always use quotes when in doubt.
  • Use meaningful variable names.
  • Export only what you need.
  • Keep variables uppercase for constants.
  • Use command substitution $( ) often.
  • Test your scripts with different values.
TIP: Variables are the foundation of flexible scripts. Quote strings, name clearly, export only what you need.
