1. READING SHELL ERRORS

Errors tell you what went wrong. Read them carefully — the message always gives a clue.

bash
./script.sh: line 10: mycmd: command not found\n./script.sh: line 15: [ : : integer expression expected\nPermission denied\nNo such file or directory
Tip: The error message always gives a clue. Look at the line number and message.

2. DEBUG MODE WITH BASH -X

Run your script with bash -x to see each command as it executes.

bash
$ bash -x script.sh\n# Example output:\n+ echo "Starting"\nStarting\n+ VAR=hello\n+ echo $VAR\nhello\n+ ls /not/exist\nls: cannot access '/not/exist': No such file or directory

3. DEBUG MODE INSIDE SCRIPT

Use set -x to enable debug inside the script.

bash
set -x\n# Your commands here\nset +x # Turn off debug
Benefit: Shows each command as it runs. Very helpful to trace issues.

4. COMMON PROBLEMS & FIXES

Six common failure categories:

A. SYNTAX ERRORS

Missing symbols or wrong structure.

if [ "${VAR}" = "x" ] echo "missing fi"

Fix: check brackets, then/fi, do/done.

B. QUOTING PROBLEMS

Wrong quotes break the script.

echo "Hi $USER" # ok echo 'Hi $USER' # literal echo "He said "hi"" # bad

Fix: use double quotes; escape inner.

C. MISSING VARIABLES

Using variables that are not set.

echo $NAME ./script.sh: line 5: NAME: unbound variable

Fix: define or use ${NAME:-default}.

D. PERMISSION ERRORS

Script or files not executable.

./script.sh: line 3: ./other.sh: Permission denied

Fix: chmod +x script.sh.

E. PATH PROBLEMS

Command not found.

mycmd: command not found

Fix: check PATH or use full path.

F. FILE MISSING

File or directory does not exist.

cat: file.txt: No such file or directory

Fix: verify path; use absolute path.

5. DEBUGGING STEP BY STEP

A repeatable workflow for fixing any script:

1. Read the error — Understand what the error says. Note the line number and message.
2. Reproduce the issue — Run the script and confirm the error happens again.
3. Run with bash -x — Use bash -x script.sh to see each command and where it fails.
4. Check variables and quotes — Make sure variables are set and quoted correctly.
5. Fix and test again — Make the change and run again. Repeat until the error is gone.
6. Remove debug — Remove set -x or stop using bash -x after fixing.
COMMON ERROR MESSAGES

What each message usually means:

  • command not found — PATH issue or typo.
  • Permission denied — missing +x or wrong owner.
  • No such file — path typo or missing file.
  • unbound variable — used with set -u.
  • integer expression expected — non-numeric in [ ].
  • unexpected token — missing fi, done, or quote.
