1. SHELL SCRIPTS IN CI/CD

Automate build, test, and deploy across every stage.

  • Run commands at every stage
  • Make pipelines reliable and repeatable
  • Handle setup, checks, and notifications

2. GITHUB ACTIONS

Use shell scripts in workflow steps.

  • Run custom commands easily
  • Prepare environments
  • Build, test, and deploy apps
github-actions
- name: Run script\n run: ./deploy.sh

3. JENKINS

Execute shell scripts in build steps.

  • Automate jobs and deployments
  • Manage environments
  • Integrate with other tools
jenkins
#!/bin/bash\n./build.sh && ./deploy.sh

4. DOCKER

Build and push images with shell scripts.

  • Build and push images
  • Prepare container environments
  • Clean up unused resources
  • Manage volumes and networks
docker
#!/bin/bash\ndocker build -t myapp .\ndocker push myapp:latest

5. KUBERNETES

Automate kubectl commands.

  • Deploy and update applications
  • Manage configs and secrets
  • Check pod and service status
kubectl
kubectl apply -f app.yaml\nkubectl rollout status deploy/app

6. CLOUD VM INITIALIZATION

Run scripts on first boot via cloud-init.

  • Install packages and tools
  • Configure users and services
  • Set up security and updates
cloud-init
#!/bin/bash\napt update && apt install -y nginx\nsystemctl enable nginx

7. DEPLOYMENT SCRIPTS

Automate deployments with rollback safety.

  • Automate deployments
  • Backup before updates
  • Rollback on failure
  • Zero- or low-downtime
deploy
./deploy.sh --env prod\n./rollback.sh

8. HEALTH CHECKS

Verify apps and services stay up.

  • Check app and services
  • Validate endpoints
  • Alert on failure
  • Keep systems reliable
health.sh
#!/bin/bash\ncurl -f http://localhost/ || exit 1

9. ENVIRONMENT VALIDATION

Fail fast if the environment is wrong.

  • Verify required tools
  • Check variables and configs
  • Validate dependencies
  • Fail fast if something is wrong
validate
command -v docker >/dev/null || {{ echo "Docker not found"; exit 1; }}

DEVOPS BEST PRACTICES
  • Make scripts idempotent (safe to re-run).
  • Always log what happens.
  • Use set -euo pipefail.
  • Validate environment before running.
  • Backup before deploying.
  • Rollback on failure.
  • Monitor after every deploy.
