18. SCHEDULING SCRIPTS WITH CRON

AUTOMATE TASKS. SAVE TIME. STAY RELIABLE.

1. WHAT CRON DOES

Cron runs commands or scripts automatically at scheduled times. Perfect for backups, cleanup, monitoring, reports, and more.

2. UNDERSTANDING CRONTAB

Crontab is your personal cron schedule.

bash
crontab -e # Edit\ncrontab -l # List jobs\ncrontab -r # Remove all jobs

3. CRON TIMING SYNTAX

Five fields: MIN HOUR DAY MONTH DOW

FieldRange
MIN0–59
HOUR0–23
DAY1–31
MONTH1–12
DOW0–6 (0=Sun)

EXAMPLES

PatternMeaning

0 2 * * *Daily at 2 AM
30 1 * * 1Mon at 1:30 AM
0 3 1 * *1st of month at 3 AM

4. RUNNING SCRIPTS AUTOMATICALLY

Add your cron job with crontab -e. Cron runs jobs in the background. No need to keep your terminal open. Great for hands-off automation.

5. ENVIRONMENT DIFFERENCES

Cron runs with a minimal environment. Your PATH, variables, and shell may be different. Use full paths in scripts. Set needed variables inside the script.

bash
PATH=/usr/local/bin:/usr/bin:/bin\nexport PATH

6. LOGGING CRON OUTPUT

Always log output for debugging. Redirect output and errors.

bash
*/5 * * * * /path/to/script.sh \\n >> /var/log/mycron.log 2>&1

7. COMMON CRON FAILURES

Watch for these pitfalls:

  • Wrong timing syntax
  • Script path incorrect
  • Script not executable
  • Missing environment variables
  • No permissions to run script
  • Output not logged
  • Cron service not running

8. SCHEDULING BACKUP & CLEANUP

Two practical scheduled-job examples:

crontab
# BACKUP JOB — daily at 2 AM\n0 2 * * * /backup.sh \>> /var/log/backup.log 2>&1\n\n# CLEANUP JOB — weekly on Sunday at 3:30 AM\n30 3 * * 0 /cleanup.sh \>> /var/log/cleanup.log 2>&1

BEST PRACTICES
  • Use full paths for commands and scripts.
  • Log all cron outputs.
  • Test scripts manually before scheduling.
  • Keep cron jobs simple and reliable.
  • Review your crontab regularly.
  • Set PATH and needed variables inside scripts.
  • Make scripts executable (chmod +x).
