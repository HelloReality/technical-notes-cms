8. Logical Operators and Multiple Conditions

Combine tests. Make smarter decisions.
1. Logical Operators
OperatorMeaningExampleDescription
&&ANDif [ $a -gt 5 ] && [ $b -lt 10 ]Both conditions must be true.
||ORif [ $a -gt 5 ] || [ $b -lt 10 ]At least one condition must be true.
!NOTif ! [ -f file.txt ]Reverses the result.
2. Short-Circuit Execution
&&
AND
If the first condition is false, the second is NOT executed.
||
OR
If the first condition is true, the second is NOT executed.
!
NOT
Flips true to false, and false to true.
Insight: Saves time and prevents unnecessary checks.
3. AND (&&)
  • Both conditions must be true.
bash
if [ -f app.sh ] && [ -x app.sh ]; then echo "File exists and is executable" else echo "Check failed" fi
Use for strict requirements.
4. OR (||)
  • At least one condition must be true.
bash
if [ -f app.sh ] || [ -f app.py ]; then echo "Script found" else echo "No script found" fi
Use for alternatives.
5. NOT (!)
  • Reverse a condition.
bash
if [ ! -f config.env ]; then echo "Config file missing" else echo "Config file exists" fi
Use to detect missing items.
6. Combining Multiple Tests
You can mix &&, ||, and ! for powerful checks.
Example 1: Mix AND & OR
bash
if [ -f deploy.sh ] && [ -x deploy.sh ] || [ -f deploy.py ]; then echo "Ready to deploy" else echo "Deployment script missing" fi
➔ Executable deploy.sh OR deploy.py exists.
Example 2: Negation + AND
bash
if [ ! -f .lock ] && [ -d /var/log ]; then echo "Safe to proceed" else echo "Lock exists or log dir missing" fi
➔ No lock file AND directory exists.
Example 3: Complex
bash
if [ -f app.conf ] && [ -r app.conf ] && ! [ -z "$1" ]; then echo "All checks passed" else echo "Validation failed" fi
➔ File exists, readable AND $1 not empty.
7. Building Safer Deployment Checks
Example: Before deploying, validate everything.
bash
if [ -f app.tar.gz ] && [ -s app.tar.gz ] && [ -x /usr/bin/docker ] && ! systemctl is-active --quiet app; then echo "All checks passed. Starting deployment..." # Your deployment commands here else echo "Deployment aborted. Check requirements." exit 1 fi
Deployment Checklist
  • File exists AND not empty.
  • Docker is installed.
  • App service is not running.
  • Proceed only when everything is correct.
  • Prevents failed or risky deployments.
