15. NETWORKING WITH SHELL SCRIPTS

TEST. MONITOR. ENSURE AVAILABILITY.
Page 17 of 20

1. CURL — SEND HTTP REQUESTS

Send HTTP requests to endpoints.

curl
$ curl https://example.com\n$ curl -I https://example.com\n$ curl -s -o /dev/null -w "%{{http_code}}" URL
Flags: -I headers only · -s silent · -o /dev/null discard body

2. PING — TEST CONNECTIVITY

Test whether a host is reachable.

ping
$ ping -c 4 google.com\n$ ping -c 4 8.8.8.8

3. SS — CHECK CONNECTIONS

Show network sockets and connections.

ss
$ ss -tlnp # listening ports\n$ ss -tnp # all connections\n$ ss -ltnp # listening with PID

4. HOSTNAME — SYSTEM NAME

Get or set the system hostname.

hostname
$ hostname # name\n$ hostname -I # IPs\n$ hostnamectl # details

5. DNS CHECKS — RESOLVE NAMES

Check DNS resolution.

dns
$ nslookup example.com\n$ dig example.com\n$ host example.com

6. HTTP STATUS CODES

Check HTTP response codes — always check status codes, not just ping!

200 OK — Success301/302 Redirect404 Not Found500 Server Error

7. TEST ENDPOINT UP

Quickly test if an endpoint is up.

test
$ curl -s -o /dev/null -w "%{{http_code}}" URL\n# 200-399 = Available\n# 400-599 = Not Available\n# 000 = No Response

8. APP HEALTH CHECK

Check if application health endpoint is OK.

health
$ curl -s https://app/health\n$ curl -sf URL && echo Healthy || echo Unhealthy
Best practice: Expose a /health endpoint in apps.

9. WEBSITE AVAILABILITY SCRIPT

Example: Check website availability.

avail.sh
#!/bin/bash\nURL="https://example.com"\nSTATUS=$(curl -so /dev/null -w "%{{http_code}}" "$URL")\nif [ "$STATUS" = "200" ]; then\n echo "[OK] $URL is UP (200)"\nelse\n echo "[DOWN] $URL is DOWN (Code: $STATUS)"\nfi

BEST PRACTICES
  • Always check HTTP status codes.
  • Use timeouts to avoid hanging scripts.
  • Check both connectivity and application health.
  • Log results for monitoring and alerting.
  • Use meaningful alerts when a service is down.
  • Test from the same network as users.
  • Keep scripts simple, clear, and maintainable.
