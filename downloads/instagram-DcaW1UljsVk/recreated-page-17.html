16. Error Handling and Safer Scripts

WRITE PREDICTABLE. RELIABLE. SAFE AUTOMATION.

1. WHY SCRIPTS FAIL SILENTLY

By default, Bash continues even when commands fail.

bash
rm file.txt echo "Deleted" echo "Script finished"
Problem: If rm fails, the script keeps running and hides the error.

2. SET -E: EXIT ON ERROR

Exit immediately if any command fails.

bash
set -e rm file.txt echo "This runs only if rm succeeds"
Benefit: Stops the script when a command fails.

3. SET -U: ERROR ON UNSET VARIABLES

Exit if you use a variable that is not set.

bash
set -u echo $UNSET_VAR
Benefit: Catches typos and missing variables early.

4. SET -O PIPEFAIL: CATCH PIPE ERRORS

Detect failures inside pipelines.

bash
set -o pipefail cat file.txt | grep "ERROR" | wc -l
Benefit: Without pipefail, only the last command's status is checked.

5. SET -EUO PIPEFAIL: STRONG & SAFE MODE

Best practice for safer scripts.

bash
set -euo pipefail
  • ✔ Exit on any command error
  • ✔ Error on unset variables
  • ✔ Catch pipeline failures

6. VALIDATING INPUTS

Always verify inputs before using them.

bash
if [ -z "$1" ]; then echo "Usage: $0 <url>" exit 1 fi
Benefit: Prevents errors and makes scripts user-friendly.

7. CHECKING DEPENDENCIES

Ensure required commands exist before running.

bash
if ! command -v curl >/dev/null 2>&1; then echo "curl not found!" exit 1 fi
Benefit: Avoids failures due to missing tools.

8. HANDLING FAILED COMMANDS

Check command results and handle failures.

bash
if ! rm file.txt; then echo "Failed to remove file.txt" exit 1 fi
Benefit: React to failures and prevent bad outcomes.

9. CLEANING UP AFTER FAILURES

Use traps to clean up on exit or error.

bash
cleanup() { echo "Cleaning up..." rm -f temp.log } trap cleanup EXIT
Benefit: Keeps systems clean even when scripts fail.

10. WRITING PREDICTABLE AUTOMATION

  • ✔ Fail fast
  • ✔ Validate inputs
  • ✔ Check dependencies
  • ✔ Handle errors
  • ✔ Clean up properly
  • ✔ Log what happens
  • ✔ Exit with the right status code

Result: Reliable and predictable automation every time.

EXAMPLE: SAFE SCRIPT TEMPLATE

bash
#!/bin/bash set -euo pipefail # Check input if [ -z "$1" ]; then echo "Usage: $0 <url>" exit 1 fi # Check dependency command -v curl >/dev/null 2>&1 || { echo "curl not found!"; exit 1; } # Function to cleanup cleanup() { echo "Cleaning up..."; rm -f temp.log; } trap cleanup EXIT # Main logic URL="$1" HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" "$URL") if [ "$HTTP_CODE" -ge 200 ] && [ "$HTTP_CODE" -lt 400 ]; then echo "[$URL] is UP (HTTP $HTTP_CODE)" else echo "[$URL] is DOWN (HTTP $HTTP_CODE)" exit 1 fi
KEY TAKEAWAY: Safe scripts = Less downtime, fewer bugs, and happier users. Always handle errors. Always clean up. Always be predictable.
