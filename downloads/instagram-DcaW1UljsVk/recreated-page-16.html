1. WHY SCRIPTS FAIL SILENTLY

By default, bash ignores errors and keeps going — hiding real issues.

{terminal('rm file.txt\necho "Deleted"\necho "Script finished"', 'bad.sh')} {callout('Problem: If rm fails, the script keeps running and hides the error.', 'danger', 'bug')}
2. SET -E: EXIT ON ERROR

Exit immediately if any command fails.

{terminal('set -e\nrm file.txt\n# runs only if rm succeeds', 'set -e')} {callout('Benefit: Stops the script when a command fails.', 'tip', 'check-circle')}
3. SET -U: UNSET VARS

Exit if you use a variable that is not set.

{terminal('set -u\necho "$UNSET_VAR"\n# fails fast', 'set -u')} {callout('Benefit: Catches typos and missing variables early.', 'tip', 'check-circle')}
4. SET -O PIPEFAIL

Detect failures inside pipelines.

{terminal('set -o pipefail\ncat file | grep "ERR" | wc -l', 'pipefail')} {callout('Benefit: Without pipefail, only the last command\'s status is checked.', 'tip', 'check-circle')}
5. SET -EUO PIPEFAIL

Best practice for safer scripts.

{terminal('set -euo pipefail', 'safe-mode')}
  • Exit on any command error
  • Error on unset variables
  • Catch pipeline failures

6. VALIDATING INPUTS

Always verify inputs before using them.

{terminal('if [ -z "$1" ]; then\n echo "Usage: $0 <url>"\n exit 1\nfi', 'validate')} {callout('Benefit: Prevents errors; makes scripts user-friendly.', 'tip', 'check-circle')}
7. CHECK DEPENDENCIES

Ensure required commands exist before running.

{terminal('if ! command -v curl >/dev/null 2>&1; then\n echo "curl not found!"\n exit 1\nfi', 'dep-check')} {callout('Benefit: Avoids failures due to missing tools.', 'tip', 'check-circle')}
8. HANDLING FAILURES

Check command results and handle failures.

{terminal('if ! rm file.txt; then\n echo "Failed to remove file.txt"\n exit 1\nfi', 'handle')} {callout('Benefit: React to failures; prevent bad outcomes.', 'tip', 'check-circle')}
9. CLEAN UP ON FAIL

Use traps to clean up on exit or error.

{terminal('cleanup() {{\n echo "Cleaning up..."\n rm -f temp.log\n}}\ntrap cleanup EXIT', 'trap')} {callout('Benefit: Keeps systems clean even when scripts fail.', 'tip', 'check-circle')}
10. PREDICTABLE AUTOMATION

Follow these rules for reliable scripts:

  • Fail fast
  • Validate inputs
  • Check dependencies
  • Handle errors
  • Clean up properly
  • Log what happens
  • Exit with the right status code

Result: Reliable and predictable automation every time.

11. SAFETY CHECKLIST

The 7 rules of safer scripts:

  • Use set -euo pipefail
  • Validate all user inputs
  • Check command dependencies
  • Handle command failures
  • Trap cleanup on EXIT
  • Log every action
  • Exit 0 / non-zero explicitly
12. WHY IT MATTERS

Safe scripts = Less downtime, fewer bugs, happier users.

Always handle errors. Always clean up. Always be predictable.

EXAMPLE: SAFE SCRIPT TEMPLATE

safe-template.sh
#!/bin/bash\nset -euo pipefail\n\n# Check input\nif [ -z "$1" ]; then\n echo "Usage: $0 <url>"; exit 1\nfi\n\n# Check dependency\ncommand -v curl >/dev/null 2>&1 || {{ echo "curl not found"; exit 1; }}\n\n# Cleanup trap\ncleanup() {{ echo "Cleaning up..."; rm -f temp.log; }}\ntrap cleanup EXIT\n\n# Main logic\nURL="$1"\nHTTP_CODE=$(curl -s -o /dev/null -w "%{{http_code}}" "$URL")\nif [ "$HTTP_CODE" -ge 200 ] && [ "$HTTP_CODE" -lt 400 ]; then\n echo "[$URL] is UP (HTTP $HTTP_CODE)"\nelse\n echo "[$URL] is DOWN (HTTP $HTTP_CODE)"; exit 1\nfi
Safe Mode — set -euo pipefail makes the script strict and safe.
Validate Input — Ensure the user provides the required input.
Check Dependency — Stop early if a required tool is missing.
Cleanup on Exit — Cleanup runs automatically on success or failure.
Main Logic — Do the work and check results.
Exit Status — Exit 0 for success, non-zero for failure.
