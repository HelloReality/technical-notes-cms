15. Networking with Shell Scripts

TEST. MONITOR. ENSURE AVAILABILITY.

1. CURL – SEND HTTP REQUESTS

Send HTTP requests to endpoints.

bash
$ curl https://example.com $ curl -I https://example.com $ curl -s -o /dev/null -w "%{http_code}" https://example.com
# -I headers only · -s silent · -o /dev/null discard body · -w status code

2. PING – TEST CONNECTIVITY

Test whether a host is reachable.

bash
$ ping -c 4 google.com $ ping -c 4 8.8.8.8
# Check connectivity · Troubleshoot reachability · Measure response time

3. SS – CHECK CONNECTIONS

Show network sockets and connections.

bash
$ ss -tuln # Listening ports $ ss -tnp # All connections $ ss -ltnp # Listening with PID

4. HOSTNAME – SHOW SYSTEM NAME

Get or set the system hostname.

bash
$ hostname # Show hostname $ hostname -I # Show IP addresses $ hostnamectl # Detailed info

5. DNS CHECKS – RESOLVE NAMES

Check DNS resolution.

bash
$ nslookup example.com $ dig example.com $ host example.com

6. HTTP STATUS CODES

Check HTTP response codes.

bash
$ curl -o /dev/null -s -w "%{http_code}" https://example.com
# 200 OK · 301/302 Redirect · 404 Not Found · 500 Server Error
Always check status codes, not just ping!

7. TEST ENDPOINT AVAILABILITY

Quickly test if an endpoint is up.

bash
$ curl -s -o /dev/null -w "%{http_code}" https://example.com
# 200–399 = Available · 400–599 = Not Available · 000 = No Response

8. CHECK APPLICATION HEALTH

Check if application health endpoint is OK.

bash
$ curl -s https://example.com/health $ curl -s -f https://example.com/health && echo "Healthy" || echo "Unhealthy"
Best practice: Expose a /health endpoint in apps.

9. SIMPLE WEBSITE AVAILABILITY SCRIPT

Example: Check website availability.

bash
#!/bin/bash URL="https://example.com" STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$URL") if [ "$STATUS" = "200" ]; then echo "[OK] $URL is UP (200)" else echo "[DOWN] $URL is DOWN (Code: $STATUS)" fi

Best Practices
  • ✓ Always check HTTP status codes.
  • ✓ Use timeouts to avoid hanging scripts.
  • ✓ Check both connectivity and application health.
  • ✓ Log results for monitoring and alerting.
  • ✓ Use meaningful alerts when a service is down.
  • ✓ Test from the same network as users.
  • ✓ Keep scripts simple, clear, and maintainable.
KEY TAKEAWAY: Automate your network checks. Detect issues early. Keep your systems and services reliable.
