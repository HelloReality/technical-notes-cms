5. READING USER INPUT AND SCRIPT ARGUMENTS

GET INPUT. USE ARGUMENTS. BUILD SMARTER SCRIPTS.
1. Read: Get User Input
  • Use read to get input from the user.
  • -p shows a prompt.
  • The value is stored in the variable.
terminal
read -p "Enter your name: " NAME
echo "Hello, $NAME"
2. Script Arguments
Pass values to a script when you run it.
SymbolMeaningExample
$0Script name./deploy.sh
$1First argumentdev
$2Second argumentus-east-1
$3Third argumentapp1
$#Number of arguments3
$@All arguments"$@"
3. Passing Arguments
Run your script with values:
terminal
./deploy.sh dev us-east-1 app1
Inside the script:
terminal
$1 = dev
$2 = us-east-1
$3 = app1
4. Validating Arguments
  • Always check if arguments are provided.
  • Prevents errors and confusion.
terminal
if [ $# -lt 3 ]; then
echo "Usage: $0 "
exit 1
fi
5. Common Practices
  • Always validate arguments.
  • Use meaningful names.
  • Quote "$@" when using all args.
  • Give helpful usage messages.
  • Exit with code 1 on error.
6. Example: Simple Reusable DevOps Script
deploy.sh
#!/bin/bash
# Check arguments
if [ $# -lt 3 ]; then
echo "Usage: $0 "
exit 1
fi
# Assign arguments to variables
ENV=$1
REGION=$2
APP=$3
# Use variables
echo "Environment: $ENV"
echo "Region: $REGION"
echo "Application: $APP"
echo "Deploying $APP to $ENV in $REGION..."
Run Example
bash
$ ./deploy.sh dev us-east-1 app1
Environment: dev
Region: us-east-1
Application: app1
Deploying app1 to dev in us-east-1...

What This Script Does

  • Checks if 3 arguments are provided.
  • Assigns values to variables.
  • Prints the values.
  • Ready to add real DevOps tasks.
TIP: Good scripts take input, validate it, and do useful work. That's the foundation of automation!
