5. Reading User Input & Arguments

Get Input · Use Arguments · Build Smarter Scripts
Read: Get User Input
read.sh
#!/bin/bash
# Prompt the user and store their answer
$ read -p "Enter your name: " name
$ echo "Hi, $name!"
Enter your name: Alice
Hi, Alice!
read pauses the script until the user presses Enter. Use -s for passwords (silent) and -t 10 to time out after 10s.

Passing Arguments
args.sh
#!/bin/bash
$ echo "Script: $0"
$ echo "Env: $1"
$ echo "Ver: $2"
$ ./args.sh prod v1.2
Script: ./args.sh
Env: prod
Ver: v1.2
Validating Arguments
validate.sh
#!/bin/bash
# Stop if the user forgot the env arg
$ if [ -z "$1" ]; then
$ echo "Usage: $0 <env>"
$ exit 1
$ fi
Validate early. Fail fast with exit 1 before any work begins.
Common Practices
Always quote: "$1"
Check $# before using args.
Use $@ (not $*) in loops.
Default with ${1:-default}
Print usage on bad input.
Example: Simple Reusable DevOps Script
deploy.sh
#!/bin/bash
# A reusable deploy script
$ set -euo pipefail
$ ENV="${1:-staging}"
$ echo "Deploying to $ENV…"
$ ./build && ./test && ./ship "$ENV"
$ echo "Done. ($?)"
Run Example
console
$ ./deploy.sh prod
Deploying to prod…
→ build OK
→ test OK
→ ship OK
Done. (0)
What This Script Does
1
set -euo pipefail — fail on any error.
2
ENV=${1:-staging} — use arg or default.
3
&& chains build → test → ship.
4
$? prints the final exit code.
Tip: Combine read for interactive prompts with positional args for automation. Same script, two modes.
